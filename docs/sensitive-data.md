# 敏感信息规范（公开仓库）

本项目是**公开仓库**（MIT 许可，任何人都能 clone、搜索、镜像）。因此仓库里**不允许**出现任何内网信息：真实主机地址、内部产品名、真实个人目录、凭据。一旦提交，即使随后删掉，内容仍留在 **git history** 里（见文末「历史问题」）。

本文件是硬性规范，配合哨兵脚本 `scripts/verify-sensitive.mjs` 执行。

## 1. 为什么

- 公开仓库会被搜索引擎、代码搜索服务、镜像站长期收录；
- 内网地址/内部产品名会暴露组织结构，并可能被用来做资产测绘；
- 凭据一旦进 history，等同于永久泄露，只能轮换；
- 文档是给外部用户看的，内网信息对他们没有意义，只有风险。

## 2. 允许 / 禁止清单

**禁止**

| 类别 | 例子（示意，勿照抄真实值） |
| --- | --- |
| 真实 IPv4（非回环） | 任意公网/内网 IP 字面量，含带端口的写法 |
| 内网域名 | 公司内网域名、企业内部域后缀、内部专用后缀、内网代码托管域名 |
| 内部产品名/前缀 | 内部系统、内部平台、内部中间件的名字 |
| 真实个人目录 | `/Users/<真实用户名>`、`/home/<真实用户名>` |
| 内部机器分区路径 | 内网大数据分区、内部专用挂载点 |
| 凭据 | GitHub token、各家 API key、AWS key、私钥、Bearer 令牌实值、密码参数实值 |
| 真实邮箱 | 任何非示例域邮箱 |
| 内部工单/内部数据 | 从内部系统抄来的标题、字段值、真实业务数据 |

**允许**

- 回环与广播地址：`127.0.0.1`、`0.0.0.0`、`255.255.255.255`（本机 lab 用）；
- `devbox`：本功能的通用术语（挂载的远端主机），保留；
- 示例域：`example.com` / `example.org` / `example.net`；
- 文档占位符（下表）；
- 抽象后的数字与结论（例如「108 条会话」可保留数字，或写「N 条会话」）。

## 3. 占位符对照表

| 场景 | 用这个 |
| --- | --- |
| 远端主机地址 | `devbox.example.com:3080` |
| 只给主机名 | `<devbox-host>` |
| Linux 家目录 | `/home/<user>` |
| macOS 家目录 | `/Users/me` |
| 示例项目路径 | `/home/user/project` |
| 示例邮箱 | `user@example.com` |
| 示例工单标题 | `示例工单标题` |
| 凭据 | `<token>`、`xxxxx`、`<redacted>` |

替换要**保留语义**：内网主机与端口 → `devbox.example.com:3080`；内部大数据分区下的用户工程路径 → `/home/you/project`。

## 4. 哨兵用法

```bash
node scripts/verify-sensitive.mjs          # 扫描所有 git 跟踪文件
node scripts/verify-sensitive.mjs --list    # 额外打印命中片段（仅在本机排查时用）
```

- 命中时输出 `文件:行 规则名`，**退出码 1**；无命中退出码 0；
- 已接入 `npm run check`（在 `npm test` 之前），所以提交前的标准动作就是 `npm run check`；
- 规则：IPv4 字面量（仅放行回环/广播）、内网域名、内部产品名前缀、真实个人目录、内部分区路径、凭据形态、真实邮箱。

**白名单是有意为之**，改之前请想清楚：

- `127.0.0.1` / `0.0.0.0` / `255.255.255.255`：本机 lab；
- `/Users/{me,user,you,somebody,alice,bob,example,dev,someone}` 与 `/home/` 同名集合：文档占位符；
- `example.com/.org/.net`：示例邮箱；
- `sk-` 规则要求 20 位以上高熵尾巴，避免把 CSS 类名之类的普通短词判成泄露。

哨兵自身也在这套规则的约束下：它的规则里用字符串拼接保存前缀（例如内部产品名前缀），这样脚本源码本身不会命中自己。

## 5. 评审检查项

- [ ] `npm run check` 绿（含 `verify-sensitive`）；
- [ ] 新增文档/示例里没有真实地址、内部产品名、真实用户名；
- [ ] 从内部系统复制的内容**先抽象再写**：工单标题、字段值、业务数据都不直接贴；
- [ ] 截图/日志粘贴前确认不含主机名、用户名、token；
- [ ] 新增「示例」时优先用本文件的占位符，不要发明新的真实值；
- [ ] 发布新版本前手动跑一次 `node scripts/verify-sensitive.mjs --list`。

## 6. 历史问题（重要，别误以为改文件就没事）

**已经进过 git history 的泄露，改文件不会自动清除。** 后续提交只是把工作树里的值删掉，历史提交里的值仍然可以被 `git log -p`、`git show`、各种 history 镜像搜到。

彻底清除需要重写历史并强推：

```bash
git filter-repo --replace-text replacements.txt   # 或 --invert-paths
git push --force --all
git push --force --tags
```

这会**改变所有提交哈希**、影响已有 clone 和 tag、需要通知所有协作者重新 clone，属于**仓库级决策**——不要在普通修复里顺手执行，先与维护者确认。轮换任何已暴露的凭据是**另一件必须做的事**，且与是否重写历史无关。

## 哨兵的两个例外（都可审计）

1. **回环地址**：`127.0.0.1`、`0.0.0.0`、`255.255.255.255` 属本机/占位语义，放行。
2. **版本号**：紧跟在 `v8=` / `electron=` / `node=` / `chrome=` / `version=` 标签之后的四段数字是版本而非地址（例如 `v8=15.2.124.28-electron.0`）。这条例外**只在标签紧邻时**生效，且写进 `scripts/verify-sensitive.mjs` 的规则注释里——如果哪天需要收紧，改那一个正则即可。

> 判断原则：宁可让哨兵多报一次、人工确认，也不要为了少一次误报而放宽对真实地址的检测。上面两个例外都是「语义上不可能是内网地址」的情形。
